# Day One Works — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** New Tarantuverse keepers add an animal in their first session, every animal gets a feeding baseline, and reminders reach keepers through push (app) or email (web) they chose.

**Architecture:** The "who is due / who needs a first feeding" rule lives only in `apps/api/app/services/feeding_status.py::compute_feeding_status`; the single-animal stats, analytics and the daily digest call it. Every account gets a `notification_preferences` row; the hourly digest adds an opt-in email channel. Mobile and web read the new status fields and change the first-run screens; per-device "already asked" state lives in AsyncStorage / localStorage behind small pure helpers.

**Tech Stack:** FastAPI + SQLAlchemy 2 + Alembic + pytest (real Postgres); Expo Router RN + jest-expo; Next.js 14 + Tailwind + `node --test`.

**Spec:** `docs/superpowers/specs/2026-10-27-day-one-design.md`

## Global Constraints

- No git writes by workers (no add/commit/stash/checkout). Ignore any "Commit" step: report instead; the controller snapshots and Cory commits.
- Never install packages into the repo or symlink into it. JS checks run in a /tmp mirror (see ENV.md in the SDD workspace).
- Neon is read-only; never call Render/Vercel/Resend from tests (EmailService is mocked).
- Never log an email address, push token or request body. `EmailService` logs subject + outcome only.
- Release cutoff constant: `FIRST_FEEDING_DUE_FROM = date(2026, 10, 28)` in `services/feeding_status.py`.
- `DIGEST_EMAIL_DAILY_CAP: int = 80` and `API_PUBLIC_URL: str = "https://tarantuverse-api.onrender.com"` in `app/config.py` Settings.
- Unsubscribe HMAC key: `hashlib.sha256(f"digest-unsub|{settings.API_SECRET_KEY}".encode()).digest()`; no expiry.
- Migration id `don_20261027_day_one`, `down_revision = "whn_20261023_whats_new_seen"`.
- Mobile: colours only from `useTheme().colors`, sizes from `TYPE`/`layout`; the design-token gate (`apps/mobile/scripts/check-design-tokens.js`) must pass without re-baselining. Web: Tailwind with `dark:` variants on everything.
- Dates the keeper picks are saved as LOCAL NOON of that day as an ISO string (never `new Date('YYYY-MM-DD')`).
- Grazers (`interval_days is None`) never get a nudge or a due flag. Paused animals never get a nudge or a due flag.
- Exact copy (use verbatim; `{name}` = nickname, else common, else scientific name):
  - Welcome: title `Welcome to Tarantuverse`, line `Let's add your first animal. It takes about a minute.`, buttons `Add your first animal` · `Import a spreadsheet` · `Look around first`.
  - Add form: label `When did it last eat?`, chips `Today` · `Yesterday` · `Pick a date` · `Not sure`, hint `Not sure is fine. We'll remind you to log its first meal.`
  - Push ask (after save): title `Want a heads-up when {name} is due to eat?`, body `At most one reminder a day, at the hour you choose in Settings.`, buttons `Turn on reminders` · `Not now`. Push ask (when due): title `Want a reminder on days something is due?`, same body and buttons.
  - Email ask (web, after save): title `Want an email when {name} is due?`; (when due): `Want an email on days something is due?`; body `On days something is due, at most once a day. You can turn it off any time.`; buttons `Email me` · `Not now`.
  - Nudge card title `First feeding not logged`; row button `When did it last eat?`; sheet chips `Today` · `Yesterday` · `Pick a date` · `Not yet`; card ✕ accessibility label `Hide for 14 days`.
  - Status labels: `needs_first_feeding` → `First meal not logged`; never fed AND `is_overdue` → `Due · no meal logged yet`.
  - Settings switch `Daily email reminder`, help `An email on days something is due, at your reminder hour.` Denied-permission button `Open phone settings`.
  - Email subject and headline `1 animal is due to eat today` / `{N} animals are due to eat today`, button `Open Feeding Day`, footer `You're getting this because you turned on daily email reminders.` + links `Unsubscribe` and `Reminder settings`.
  - Unsubscribe page: ok `You're unsubscribed from daily email reminders.`; bad token `This unsubscribe link isn't valid.`

## Review Focus

1. A keeper west of UTC adds an animal at 9 pm local: the baseline must be that LOCAL day, not tomorrow (Task 1 test `test_baseline_uses_local_day`).
2. A paused never-fed animal: no nudge, not due (Task 1 test `test_paused_never_fed_no_nudge`).
3. Digest email to an inactive, merged (`@merged.invalid`) or test-domain account must not send (Task 2 test `test_email_skips_unreachable_accounts`).
4. Unsubscribe link for a deleted account or a tampered token: no 500; deleted → 200 with the ok message (idempotent), tampered → 404 (Task 2 test `test_unsubscribe_tampered_and_deleted`).
5. Import row with an unparseable or future last-fed: a row error, no feeding written, other rows still import (Task 3 test `test_import_last_fed_invalid_and_future`).
