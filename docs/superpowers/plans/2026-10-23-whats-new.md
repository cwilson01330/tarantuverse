# What's New Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An in-app "What's new" — a repo-file feed served by the API, a dismissible Home card, a history page and a sidebar/Profile entry — in TV web, TV mobile, HV web and HV mobile.

**Architecture:** `apps/api/app/content/whats_new.json` is validated and cached by a small service; one router returns the feed + the card's `unseen` list and records "seen" in two `users` date columns. Each app has a `whats-new` lib (API calls, per-session cache, its own target→route map) feeding a card and a page.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, Pydantic v2, Postgres; Next.js (TV web, HV web); Expo Router RN (TV mobile, HV mobile).

**Spec:** `docs/superpowers/specs/2026-10-23-whats-new-design.md` — read it first; this plan adds file names, signatures and tests only.

## Global Constraints

- **No git write commands.** Tasks end by listing changed files; Cory commits.
- Migration `whn_20261023_whats_new_seen`, `down_revision = "exp_20261022_expenses"`; columns `users.whats_new_seen_tv`, `users.whats_new_seen_hv` (DATE, nullable).
- Targets exactly: `expenses, feeding_day, analytics_advanced, collection, species, settings`.
- Entry limits: id `^\d{4}-\d{2}-\d{2}-[a-z0-9-]+$` ≤ 80; `published_on` ≥ 2026-10-01; title 1–60; body 1–220; action label 1–30; plain text.
- `unseen` = live entries (`published_on <= UTC today`) with `published_on > max(created_at UTC date, seen column)` AND `published_on >= Monday of (newest live entry's ISO week − 1 week)`; newest first. `weeks` = all live entries grouped by ISO-week Monday, newest first. Future-dated entries never returned.
- `POST /whats-new/seen` sets the app's column to the newest live `published_on`, never moving backwards; empty feed → unchanged.
- Router is NOT a collection router (no `@policy`, not in `COLLECTION_ROUTERS`); auth via `get_current_user`; `POST` `@limiter.limit("30/minute")`; no `from __future__ import annotations` in the router.
- Card: up to 3 entries, "Premium" label when `premium`, ✕ and any action button call `markWhatsNewSeen` then (actions) navigate; "See all" → page. Page never marks seen. One `GET` per app session, cache shared by card, dot and page.
- Copy follows the honesty principle; never mention other platforms or prices.
- TV web light + dark; HV web dark-only; mobile theme tokens only; JS-only (OTA).
- Scratch only under `/tmp/tv`; JS checks in the Linux mirror `/tmp/tv/repo`.

## Review Focus

1. **Keeper who signed up mid-week** — an entry published the day BEFORE signup is never on their card, one published the day AFTER is. Test in Task 2.
2. **Dismissed, then a new week lands** — only the new week shows, not the dismissed one. Test in Task 2.
3. **Draft committed ahead of its date** — absent from both `unseen` and `weeks` until that date. Test in Task 2.
4. **Feed edited to remove the newest entry after keepers dismissed it** — `POST /seen` must not move the marker backwards. Test in Task 2.
5. **An app with no button for a target** (e.g. HV `analytics_advanced`) — the entry renders without a button, never a dead link. Target-sync test in Task 3 requires an explicit `null`.
