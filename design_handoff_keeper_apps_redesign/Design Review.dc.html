Design review

Tarantuverse & Herpetoverse

Two sibling keeper apps built from one codebase that have quietly drifted apart. Below: every screen recreated from source, next to a proposed revision. The brief was flow, consistency, and surfacing what's already there — so the recommendations are almost entirely about hierarchy and discoverability, not repaint. The gradient stays.

Feeding is the weekly job Photos are the point Density 7/10 Emoji → MDI icon set Keep the gradient

Seven findings

01Nine features are unreachable

In Tarantuverse's tab layout, Search, Enclosures, Forums, Species and Scorpions are all declared href: null — routable but invisible. Analytics, Breeding, Feeders and Import only exist inside a Quick Actions grid at the very bottom of the dashboard. This is the discoverability problem you described.

02Feeding is buried under stats

The job users do weekly sits fifth on the page: four equal-weight stat tiles, then the Feeding Day button, then the alert list. "Needs Feeding" and "Feeding Alerts" are the same data rendered twice, 400px apart.

03Photos are treated as thumbnails

Tarantuverse grid cards give the photo 150px and then cover its four corners with badges — the premolt badge and the taxon glyph both claim bottom-left. Herpetoverse rows give the photo 56px. For a hobby that's this visual, the animal should be the largest thing on screen.

04The two apps have drifted

Herpetoverse's dashboard is a port of Tarantuverse's, but the values slid: stat icon 40 vs 36px, stat value 24 vs 26px, section title 18 vs 17px, alert thumb 40 vs 42px, feed row radius 12 vs theme. Tarantuverse renders emoji inside its stat icon boxes; Herpetoverse renders MDI icons in the same slot.

05Emoji are doing icon work

🕷️ 🦋 🔮 🍽️ 📊 👥 ✅ appear as section markers, stat glyphs, filter chips and placeholder art. They render differently per OS, can't take a theme color, and can't be sized on the 4pt grid. Both apps already depend on MaterialCommunityIcons — the set is right there.

06Herpetoverse has no light mode

Tarantuverse ships createLightColors() plus eleven species themes and two density presets. Herpetoverse exports a single hardcoded darkTheme object. Same context shape — porting the light branch is a small, high-value change.

07Tool actions hide in 22px header icons

Herpetoverse's collection header stacks four unlabeled 22px glyphs — bell, freezer, import, fork. Two of them (Feeders, Feeding Day) are core weekly flows. Nothing tells a new keeper the freezer icon is an inventory system.

Feeding becomes the page, not a tile

"Needs Feeding" and "Feeding Alerts" merge into one card: count, taxa breakdown, Start button, and the three most-overdue animals with a one-tap check-off. Everything the weekly loop needs, above the fold, no scroll.

"31 days" → "17d overdue"

The server already computes a species- and life-stage-aware is_overdue. Show the delta, not the raw day count — 31 days means nothing without knowing the target for that species.

Vanity stats shrink, tools appear

Total Molts and Premolt Alerts are reference numbers, not actions — they drop to a compact three-up strip and gain Feeder stock, which currently has no dashboard presence at all. The space buys an eight-tile "Everything else" grid that surfaces Enclosures, Forums and Import for the first time.

Header carries the count

"62 animals · 18 species" as a header subtitle retires the My Collection tile entirely — and matches Herpetoverse's existing capSubtitle pattern, so the two apps converge on one header. Search returns to the header where users look for it.

Five tabs, shared with Herpetoverse

Home · Collection · Species · Community · You. Species stops being an href: null orphan, and both apps run the same spine with one swapped slot (Community here, Breeding there).

One screen of chrome before one animal

Premolt banner, search, taxon chips, sort chips, title + view toggle, stats card — six stacked bands, roughly 430px, before the first card. On a 62-animal collection the keeper scrolls past all of it every single time. Search and filters move into the header; sort joins the filter row as an icon; the stats card is deleted (it duplicates the dashboard).

Filter chips carry counts

Today all eleven taxon chips render whether or not the keeper owns any — Herpetoverse already solved this with ownedTaxa. Port that, add counts, and lead with a "Due 7" filter so the collection screen answers the feeding question too.

Four corner badges → one status line

Today the feeding pill, sex badge, premolt badge and taxon glyph all overlay a 150px photo — and premolt and taxon are both positioned bottom-left, so they collide. Proposed: photo goes 4:5 and only sex (and premolt, when active) overlay it; feeding status becomes a dot + label in the card footer where it can be read at a glance and colored by theme.

Name first, species second, stop repeating

The current card prints common name in the title and again on the third line — "Brazilian Red and White Tarantula" twice, four lines tall. Keeper name → scientific name, two lines, always.

Bug caught in your own store screenshot

The second card in app_screens/01.png reads "✓ nulld ago" — a null day count string-concatenated into the badge. Guard for never-fed and render "Not yet fed".

The best content in the app is unreachable

312 care sheets across ten taxa, and the route is href: null. The only entry points are a 24px book icon in the Collection header and a Quick Actions tile below the dashboard fold. This is the strongest argument for the five-tab spine: Species earns a permanent tab.

260px of filters before one species

Title block, "Browse by animal type" label, ten-pill segment, search, "Care level" label, four chips, then a result count. Search moves into the header; taxon and care level merge into one count-bearing chip row; the labels go.

Ten taxon pills is a menu, not a filter

The scroller hides seven of ten options off-screen with no affordance, and a keeper who only owns tarantulas still scrolls past Vinegaroons, Roaches and Other. Chips carry counts and lead with All, so the catalog is cross-taxon by default and the taxon becomes a narrowing action.

Rows beat a 2-up photo grid here

Unlike the Collection, most catalog entries have no photo — they render a 160px block of emoji. Rows fit the same information in less height, give the care level and venom tier room to be words instead of a colored circle containing "⚡", and let biome, size and hemisphere sit on one scannable line.

Care level is encoded as a colored circle

Today the card shows a 28px badge containing ✓, ⚠, ⚡ or ? — no text anywhere. Nothing teaches the mapping, and colour alone fails for colour-blind keepers. Say "Beginner" / "Advanced".

Give the database a reason to be opened

A "Good for beginners" shelf costs one query on data you already have (care_level, times_kept) and turns a lookup tool into something browsable. Obvious follow-ups: "Species you keep", "Most kept this month", "Communal-safe".

A care sheet with no call to action

A keeper researching a species and deciding to buy it has to back out, find Collection, tap the FAB, choose a taxon, and retype the species. A pinned "Add to collection" bar prefilled with this species is the highest-value change on the screen.

Two stacked warning blocks for one idea

"MEDICALLY SIGNIFICANT VENOM" in all-caps with a ⚠️ inside a red-bordered block, then a second orange block for urticating hairs — 150px of alarm before any husbandry data, and the same facts repeat inside the Behavior accordion. One calm rule line covers both; the hero badges already flag the danger.

Everything useful is collapsed

Five accordions all default closed, so the sheet opens as a list of five grey bars. Expand Enclosure by default — it's the reason people open a care sheet — and let the collapsed rows preview their contents ("Adult 1×/wk", "India · Skittish") so the screen answers something before any tap.

Quick Stats as 📏📈🌡️💧

Four emoji over four values in a wrapping row. Same data, MDI icons, one line of four — and it fits above the fold alongside the safety line.

Two care-sheet implementations

Tarantulas render /species/[id]; every other taxon renders /invert-species/[id]. Two screens to keep in sync forever. Since the browser already normalises all ten taxa into one Row union, the care sheet can do the same — one screen, taxon-conditional sections.

Bookmarks and compare

Two small additions that fit how people actually shop for a species: save a shortlist, and compare two sheets side by side. Both are additive and don't touch the data model much.

Four decisions before one keystroke

Taxon → route → form mode → step. None of them are things the keeper is thinking about; they're thinking "I just got a Red Knee." Search for the species first and every one of those resolves itself: the species record carries the taxon, which picks the route, and there is only one form.

Two rows in the picker are indistinguishable

Scorpion and Vinegaroon both render 🦂; Tarantula and True spider both render 🕷 — the source even comments on running out of glyphs. The sheet also has no ScrollView, so on a 375×812 phone the last two of eleven rows (including Colony) fall off the bottom.

22 fields to log one spider

Species lookup, common name, scientific name, nickname, sex, life stage, date acquired, last fed, source, enclosure type, enclosure size, substrate type, substrate depth, last substrate change, temp min/max, humidity min/max, misting, notes. Every one optional. Two of them matter.

Prefill husbandry from the care sheet

This is the change I'd make first. The species record already holds enclosure size per life stage, substrate type and depth, temperature and humidity ranges — the form asks the keeper to retype what the database already knows. Pick a species, get sensible defaults, override anything. It also makes the 312 care sheets pay for themselves.

The mode toggle is a symptom

"Guided" vs "All fields" exists because the form is too long either way — a three-step wizard for optional data, or one endless scroll. Progressive disclosure removes the choice: required fields visible, everything else in three collapsed rows that preview their own contents.

Save is never far away

Today the primary button says "Next →" and Save only appears on step 3 (or in the header, but only in quick mode). Proposed: a pinned bar naming what you're about to add, live the moment a species is chosen, plus an "add another" affordance for keepers unboxing a shipment of slings — and Import in the header for the ones arriving with a spreadsheet.

Colonies

Colony keeping is fundamentally about whether the population is growing, and nothing on either screen answers that. The event stream already holds every delta needed to.

Show the trend, not just the number

"~840" answers nothing on its own — a roach keeper needs to know if the bin is producing. The events table already stores count_delta with occurred_at, so a 12-week bar series and a "+106 last 30 days" figure are a reduce over data you have. This becomes the reason to open the screen.

Stage buckets as proportion bars

Two boxes reading 180 and 660 don't communicate that the colony is 79% nymphs — which is the health signal. Same data, horizontal bars, and it stays legible as keepers add custom buckets.

Eleven event types, four of them frequent

The add-event panel offers birth, death, added, removed, cannibalism, aggression, molt found, split, merge, observation and count correction as equal emoji chips — and only after tapping "+ Add event" and scrolling to it. Promote the four common ones to buttons at the top; the rest live behind "More" in the sheet.

Events should read as sentences

"Birth / +120 nymphs · Jul 14" is a database row. "120 nymphs hatched · 13 days ago" with the delta right-aligned and colour-coded is a log entry. Also: the delete ✕ sits inline on every row today — move destructive actions to a swipe or long press.

A 150px photo of a roach bin

Unlike an individual animal, nobody opens a colony to look at it. Demote the photo to a thumbnail beside the title (or drop it) and give that space to the population card.

Feed-out closes the loop

Most invert keepers run a roach or isopod colony as a feeder source, and the app already has a Feeders inventory. A "Removed" event that also credits feeder stock would join two features that currently don't know about each other.

Stop pretending a colony is an animal

Today the colony card is the same photo card as a tarantula, with three overlays fighting for the image — a "Colony" tag top-right, the count top-left, and a taxon glyph bottom-left that duplicates the placeholder emoji directly behind it. A keeper scanning the grid sees one more spider.

Give it a full-width row

Colonies are few and structurally different, so they break the 2-up grid rather than sit inside it — pinned above the animal cards under a "Colonies" label. The row carries what actually matters: headcount, 30-day trend, and the stage split as one proportion bar. No overlays, no photo competing with data.

One "Colony" concept, two entry points

Colony lives as row 11 of the taxon picker (below the fold, no scroll) with the hint "Track a communal/colony population" — explaining the concept to someone who has to already understand it to find it. In the proposed add flow it becomes a toggle on the add screen: "one animal" vs "a population", set after the species is chosen, when the choice is concrete.

Same skeleton as Tarantuverse

Feeding hero → three-up stat strip → tools grid → tab bar, identical structure and identical spacing values. The apps stay distinct through color and iconography, not through layout divergence — which is what makes them feel like separate products today.

A gradient of its own

Tarantuverse gets electric blue → neon pink; Herpetoverse gets a deep emerald fade into the background. Quieter, because reptile keeping reads calmer, but unmistakably the same family. layout.useGradient is already in the HV theme, just unused.

Two Quick Actions is not a grid

The current five-tile grid duplicates Add and Feeding Day, both already elsewhere on the page. Meanwhile the morph calculator, QR photo upload, weigh-in and shed logging — real, shipped features — have no home. The eight-tile surface is where they go.

Make the free-tier cap legible

"3 / 5 animals" currently appears twice as 11–12px grey — as the header subtitle and again in the stat card footer. Once in the header, plus one honest upgrade row at the bottom of the page where it isn't blocking the feeding job.

Ship light mode

Herpetoverse's ThemeContext exports one frozen dark object. Tarantuverse's has the whole light branch, plus eleven species palettes and the Keeper/Hobbyist density presets. Porting that context wholesale gets Herpetoverse light mode, theming and density in one change — and puts both apps on one theme API.

Four unlabeled header glyphs → one

Bell, freezer, tray, fork at 22px with no labels. Feeders and Feeding Day move to the labeled tools grid on Home; Import moves into the add flow; the bell stays. Search, filter and layout take the header instead — the three things a list screen actually needs.

The right-side indicator stack is misaligned

Sex chip, day pill and Fed button sit in one row, but the Fed chip carries marginTop: 6 inside an alignItems: center row, so it hangs low against its siblings. It's visible in the shipped build.

"11d" doesn't say overdue

The pill colour encodes urgency but the number doesn't, and colour alone fails for colour-blind keepers. Same fix as Tarantuverse: state the delta in words, keep the colour as reinforcement.

Quick actions on the card, not in a long-press

Mark fed, log shed and log weight already exist in AnimalActionSheet — behind a long press that nothing advertises. Surfacing them as a three-button row on each card makes the whole husbandry loop one tap, and is the single biggest discoverability win in this app. The card knows when an animal is CGD-fed, so the primary button relabels itself to "Refresh CGD".

Morph belongs on the card

For breeders, "Pastel het Clown" is the identity — more so than the scientific name. It's already in the genotype data; append it to the species line.

The name renders twice in 100px

AppHeader title={animalTitle(animal)} and ReptileHero title={animalTitle(animal)} both render "Kaa", stacked. Give the hero the name and let the photo go full-bleed — the same treatment as the species care sheet, so detail screens across both apps rhyme.

Three cards to say one thing

FeedingStatusBanner, FeedingIntelligence and CgdRefreshSection stack before the log buttons, all about the same question. Merge into one card: the verdict as a sentence, the reasoning as a subtitle, the action as a button. CGD just relabels the button to "Refresh CGD".

One timeline, not three lists

Recent weigh-ins, Recent feedings and Recent sheds are three lists of identical shape, each sorted independently. A keeper wants to know what happened to this animal, chronologically — one interleaved timeline with a type filter answers that, and collapses three sections into one.

Logging is the job — make it a bar

Today's log actions are outlined secondary buttons sitting mid-scroll, and each opens a full form. Pin them, and let the overdue card carry a one-tap "Fed — small rat" that reuses the last meal (the mechanism already exists as quickFeedAnimal) with a tune icon for the full form.

11px letterspaced section titles

sectionTitle is 11px/700 with letterSpacing: 1.5 — below the app's own 12px caption floor, and five of them in a row give the screen no hierarchy at all. Take the 12px uppercase label used elsewhere in the proposal and use it in both apps.

Surface the acceptance rate

Feeding records already carry an accepted flag, and refusal streaks are the earliest signal something is wrong. "92% · 24 of 26" in the stat strip costs one derived value and is the number a serious keeper actually wants.

Add: taxon first, species fourth

This form is already better than Tarantuverse's — one screen, sensible fields, taxon-aware placeholders. But it still opens with a required taxon choice, then asks for Name, then Species, then Common name. Apply the same inversion: species search first, taxon derived from the record, common name filled automatically instead of typed.

Add: no genetics field

For a ball python keeper, the morph is the animal — but the add form has no genotype input, so every new snake has to be saved, reopened, and edited via the Genetics section. Put the gene picker on the add screen for snakes.

Add: "Feeds on CGD" is unexplained

A bare toggle with no hint, on a screen a new keeper sees before they know the app changes feeding cadence based on it. Default it from the species (crested geckos already resolve it server-side) and only show the override when the species is ambiguous.

Breeding: 110px of onboarding copy, permanently

A kicker, a title that repeats the header, and a three-line paragraph about privacy defaults render on every visit for the rest of the app's life. Move it to the empty state and the new-pairing form, where it's actually needed.

Breeding: dates, not status

A pairing row says "Paired Mar 3 · separated Mar 9 · 🐍 Snake". Breeding season is a sequence of milestones — pairing, ovulation, prelay shed, lay, hatch — and the keeper's question is always "what's next and when". A four-stop progress track with a stage pill and a countdown answers it at a glance; the copy already promises clutches and offspring the tab doesn't show.

Breeding: connect the morph calculator

The calculator exists at /morph-calculator and can be deep-linked with a snake, but the Breeding tab never mentions it — yet a pairing is exactly two parents with known genotypes. Offer the projection from the pairing card and from the header.

Every icon, verified

How to read the icons in this document

This document renders icons as an MDI webfont, so the markup looks like <i class="mdi mdi-silverware-fork-knife">. In the app that is <MaterialCommunityIcons name="silverware-fork-knife" /> — strip the mdi- prefix and use the rest as the name prop. MaterialCommunityIcons is the MDI set, so the names are identical.

Every name below was checked against the glyph map already installed in your repo — apps/mobile/node_modules/@expo/vector-icons/build/vendor/react-native-vector-icons/glyphmaps/MaterialCommunityIcons.json (@expo/vector-icons ^15.0.2). All of them resolve.

The one name that does not exist is lizard. There is no lizard glyph in MDI. Use turtle for a generic non-snake herp, or keep snake as the taxon fallback. An unknown name renders an empty box silently — it does not throw.
